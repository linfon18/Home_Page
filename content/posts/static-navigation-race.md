以前在小站点开一篇文章，右下角的蓝龙会跟着主文档一起销毁。再从文章返回，模型又要初始化一次。换成局部导航后，我又给列表里的标题加了过渡，让它从点击位置移到新文章的标题位置。做这个过渡时得照顾加载失败和快速连点，否则容易出现标题和正文不是同一篇的情况。

## 点两次链接，要等哪一篇

`navigation.js` 只接管满足条件的同源链接。按 Ctrl 打开新页、下载、外链这些行为交给浏览器。普通点击会进入 `navigate`，递增 `serial`，并中止上一轮 fetch。读回 HTML 并解析以后还要检查 `id === serial`，才允许应用结果。

```text
0ms    点文章 A，serial = 1，请求 A
20ms   点文章 B，serial = 2，中止 A，请求 B
70ms   B 返回，编号匹配，替换正文、更新标题和地址
90ms   A 的旧路径结束，编号不匹配，退出
```

编号检查也放在 `finally`。慢的旧请求即使已经被中止，也会运行收尾。如果它能无条件关进度条，B 尚未完成时进度条就会消失。代码检查当前编号后才清掉 `navigating` 并收尾。这里同时管住页面内容与加载状态。

## 先卸载旧正文里的监听

换页时先记下原来标题的屏幕坐标和字号，发 `site-page-before`，再 `SitePage.dispose()`，然后换 `#main`、页尾签名、导航选中状态与 `title`、canonical 等元数据。Live2D 容器在 `#main` 外面，可以留在原位。新正文挂载并恢复滚动位置后，再测新标题的坐标和字号。两点之差用于 `translate`，字号比例用于 `scale`，用 Web Animations API 从旧标题的位置归到新标题的位置。减弱动态效果模式和原题已经离开视口的情况跳过这一步。

如果文章之前读到屏幕下方，点到别页再按后退，`popstate` 用相应历史项保存的 `siteScroll`。带 `#section-2` 的站内导航没有历史位置时，先定位到锚点。

我会把同一篇文章分别用直达、站内进入、按返回进入来对比。预期三次的标题、正文和 canonical 一样。第二轮给 A 的请求加延迟，在 B 已经挂载后让 A 结束，再看地址和进度条。如果发布期间新 HTML 引用的脚本或样式清单与当前文档不同，代码会走完整导航，让资源和正文一起更新。能保留 Live2D 的前提是两页用着同一批外壳资源。
