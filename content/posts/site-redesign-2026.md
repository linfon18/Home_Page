2026-11-16 增补：背景星点与连线使用独立的 2D canvas，和半透明面板分开绘制；导航滑块、页面转场及滚动入场通过 CSS 和 Web Animations 实现。页面切走时断开观察器、取消尚未结束的入场动画，背景画布跨页复用，并在后台、弹窗和减少动态效果时停止绘制。Live2D 增加 50%–200% 的大小设置，保存用户比例后，按当前视口限制最终尺寸，再调整渲染器和模型缩放，因此网格命中和放大镜仍使用同一坐标系统。

同日终端更新：命令解析移入 `terminal-shell.js`，先按引号与操作符分词，再执行管道、重定向及条件链。命令共享内存文件、暂存区和服务状态，因此修改文件后可以继续筛选、编译和提交，停止 Nginx 后的本地 `curl` 也会报连接失败。`sha256sum` 根据文件内容计算摘要，`tar` 保存内存快照；它们仍不访问访客的真实文件系统。自动操作新增配置排障、传输、DNS、系统调用、构建测试等八组流程。

天气与前台程序增补：`weather.js` 直接读取 wttr.in 当前天气的 WWO 编码，映射为雨、雪、雾或冰粒效果。页脚选择自动、手动天气或关闭，偏好与城市保存在浏览器；请求有超时和缓存过期处理。独立 Canvas 在后台、弹窗和减少动态效果时停止调度，切页继续复用。Live2D 的 MAX 根据可视视口同时约束宽高，窗口和软键盘变化时更新画布，仍遵守渲染像素预算。

交互终端的 `sl`、`top` 与 apt 安装由 `terminal-programs.js` 管理前台生命周期：启动时取得显示区，退出、中断或切页时清理计时器并归还提示符。自动场景只在实际输入后让出画面，因此悬停保留原帧，交互时也不会上下叠放两个终端。空回车保留 shell 退出码，按键重复直接提交空行；输入法组合事件单独处理。apt 的安装目录、确认、进度及状态是有限模拟，不能替代真实包管理器。

手机终端另设触屏接管状态，指针离开、输入框失焦和软键盘改变视口都不会释放它；只有点按终端外部才开始恢复计时。Live2D 清晰度则分别处理可见画布与 Cubism 遮罩：画布使用设备像素倍率和缩放比例，并限制总像素数；遮罩从默认的低分辨率调整为 512/1024。改变遮罩尺寸后重新绑定 WebGL 上下文，隐藏期间视口发生变化时，在重新显示前同步尺寸，避免放大旧画布。

这次重构有两个明确约束：网站部署在 EdgeOne 静态托管上，构建环境只预装 Node.js 14；页面需要实时玻璃效果、可接管的终端和 Live2D，同时保留可直接访问的文章页面。

最终采用构建时生成 HTML、浏览器端渐进加载交互的结构。下面按源码说明几个具体问题：静态页面怎样生成，玻璃怎样跟随 DOM，终端为什么会闪，以及模型动作怎样避免互相覆盖。

## 1. 用 Node.js 14 生成独立页面

构建入口是 `build.js`，只使用 Node.js 内置模块。浏览器侧的 PixiJS、Cubism 等运行库保存在静态资源目录，因此“没有构建依赖”不代表前端没有第三方库。

源码中的主要职责如下：

```text
build.js                  读取内容、输出页面和索引
site/template.js          公共导航、页脚和页面布局
site/publishing.js        文章列表、正文和目录
site/seo.js               canonical、分享标签和 JSON-LD
content/posts/            文章 Markdown
content/notes/            笔记 Markdown
site/assets/              样式、交互脚本及模型资源
```

每次构建读取 Markdown 文件头，跳过 `draft: true` 的内容，再按发布日期倒序排列。同一份内容数组用于生成详情页、首页最近更新、文章列表、搜索索引、RSS 和 sitemap，避免新增文章后还要维护几套入口。

文章会输出到 `dist/articles/<slug>/index.html`。浏览器直接请求这个地址就能拿到正文，刷新子页面也不需要 SPA 路由回退。JavaScript 负责搜索、动画和交互，正文不依赖客户端请求后再拼装。

站内切页由 `navigation.js` 拦截普通的同源链接，获取目标静态 HTML，只替换 `#main` 和页面元数据，顶部显示细加载条。导航、玻璃画布、鼠标和 Live2D 留在同一文档里。`page.js` 为正文模块提供挂载和清理入口，切走时取消请求、计时器与文档监听，进入新页后重新绑定。后退、前进通过 History API 恢复地址和滚动位置；直接打开链接仍返回完整静态页面。

文件头是当前项目自己的简化格式：逐行按第一个冒号拆键值，标签按逗号分隔。它没有实现完整 YAML，不能把任意 YAML 配置直接放进来。正文渲染器同样只覆盖本站需要的 Markdown 子集，原始 HTML 会先转义。

部署脚本的安装阶段不下载框架，构建阶段调用 `node build.js`：

```bash
bash 部署.sh install
bash 部署.sh build
```

EdgeOne 的输出目录设置为 `dist`。本地可用 `SKIP_GITHUB_SYNC=1 node build.js` 跳过头像联网同步；正常构建会尝试获取 GitHub 头像，失败时保留仓库内的快照。favicon 在构建时将同一头像内嵌到 SVG，再用圆角裁剪路径裁切。

## 2. 用圆角距离场计算玻璃边缘

玻璃绘制在 `site/assets/glass.js`。页面共用一个全屏 WebGL 玻璃画布，文字、链接和按钮仍由 DOM 渲染；Live2D 有独立的渲染画布。

每帧通过 `getBoundingClientRect()` 读取可见面板的位置，把矩形和圆角半径传给着色器。片元先判断自己属于哪个面板，再计算到圆角矩形边界的有符号距离：

```glsl
float rounded(vec2 p, vec2 halfSize, float radius) {
  vec2 q = abs(p) - halfSize + radius;
  return length(max(q, 0.))
       + min(max(q.x, q.y), 0.) - radius;
}
```

距离为负表示在面板内部。对这个距离场沿 X、Y 方向做数值差分，可以得到边缘朝向；再根据距边缘的深度构造一个凸起表面的法线 `surfaceNormal`。靠近边缘时法线倾斜，内部逐渐趋于平坦。

当前着色器使用 1.46 作为材质折射率，通过下面的偏移重新采样背景：

```glsl
vec3 ray = refract(
  vec3(0., 0., -1.), surfaceNormal, 1. / 1.46
);
vec2 bend = ray.xy / max(abs(ray.z), .2) * 30.;
```

背景图加载后，还会预先生成一张模糊纹理。内部主要采样模糊图，边缘增加清晰纹理的比例，再叠加通道偏移、亮边、内侧暗边和鼠标附近的高光。点击产生的波纹也只改变采样位置与亮度。

这里实现的是针对固定背景的视觉近似。采样源是本站的背景插画，没有将任意 DOM 抓成纹理，所以不能正确折射玻璃下面滚过的正文或 Live2D，也没有做完整的三维光线路径计算。

导航还涉及层级问题：全屏画布在正文下面，单靠它无法遮住滚到导航背后的文字。实现中将同一次 WebGL 绘制结果复制到导航自己的 2D canvas 层里，让材质处于导航的层叠上下文内，导航文字继续保留为 DOM。

页头曾在滚动超过 12px 时缩小 padding。这会改变文档高度，浏览器的滚动锚定又把位置拉回阈值附近，导致收缩状态反复切换。修复时保持页头占位高度不变，只通过 `transform` 上移内部导航，因此视觉收缩不再改变文档流。

绘制节流间隔是 32ms，分辨率倍率在窄屏上限为 1.25，其余上限为 1.35；实际帧率仍取决于设备。文章面板会增加保护文字的底色。WebGL 初始化失败或上下文丢失时，则保留 CSS 玻璃样式。

## 3. 终端接管时保留原来的 DOM

终端拆成了两部分：`linux.js` 负责自动场景，`console.js` 负责交互命令。gcc、gdb、vim、apt、sudo、sl 等都在浏览器内模拟，没有连接真实 Shell。

自动播放不是单独播放一段录像，而是异步推进的场景函数。输入记录包含命令文本、光标位置和光标前后的文本节点，因此可以插入错字、退格、移动光标和模拟 Tab 补全。场景及参数会变化，但它仍是有限场景的组合，不能保证永不重复。

暂停的关键是保留异步任务的剩余等待时间。以下是 `linux.js` 的等待函数展开后的写法：

```javascript
async function wait(ms) {
  let remaining = ms;
  while (remaining > 0 && !closing) {
    const slice = Math.min(remaining, 60);
    await new Promise(resolve => setTimeout(resolve, slice));
    if (!paused && !interacting && visible) {
      remaining -= slice;
    }
  }
}
```

鼠标进入后，交互模块发送 `terminal-interaction` 事件，自动模块停止扣减剩余时间。离开五秒后解除交互状态，原来的场景函数继续执行。用户手动暂停的 `paused` 状态独立保留，不会因一次移入移出就被恢复播放。

此前切换时闪一下、提示符颜色消失，原因在于接管时重新创建了输出和命令行。修正后，进入区域只记录当前命令行，并将 `dirty` 设为 false；没有真实输入就不改它：

```javascript
function paintInput() {
  if (!active || !dirty || mode === 'vim' || mode === 'ping') {
    return;
  }
  // 首次输入后，再接管当前行的绘制。
}
```

第一次输入时，原行的子节点会移入 `DocumentFragment` 暂存，交互层在该行绘制带颜色的提示符。恢复时把原节点放回去，因此自动任务仍持有同一批文本节点和光标引用。它不需要重放之前的输出。

交互文件系统是内存中的 `Map`，Vim 保存只更新当前页面内存。普通输出最多保留 90 行，避免长时间打开后节点持续增长。ping 则单独维护定时器、已发送数量和有效延迟样本；Ctrl+C 停止计时后计算丢包率及 min/avg/max/mdev。延迟样本来自本地模型，不是实际网络测量。

## 4. Live2D 的命中检测与动作混合

**蓝龙并非我自己的原创角色设计**，Live2D 来自 [Bilibili 视频 BV13Mg66xEAa](https://www.bilibili.com/video/BV13Mg66xEAa)。本站增加的是网页接入、命中检测和交互控制，原模型使用须知随源码保留。

模型加载前先检查视口和输入设备：

```javascript
const desktop = matchMedia(
  '(min-width: 768px) and (hover: hover) and (pointer: fine)'
);
```

最初把这个判断放在加载运行库之前，而不是模型下载后再用 CSS 隐藏。后续已移除设备加载限制，手机也会加载并显示同一模型；窄屏或粗指针设备使用更小的角色尺寸和 30fps 绘制上限。画布按屏幕像素密度渲染，最高 4 倍，并限制手机总画布像素不超过 300 万；桌面对应为 36fps 与 400 万像素。点按沿用下面的网格命中逻辑，关闭和恢复的偏好跨页保留。

点击也没有直接使用覆盖整个角色的矩形。指针先通过 `toModelPosition()` 转为模型坐标，再按绘制顺序从上往下检查可见网格：包围盒做粗筛，三角形内部测试做细筛，命中后沿部件的父级关系识别头部、脸、耳朵、身体、翅膀和尾巴。

外层容器与 canvas 使用 `pointer-events: none`，文档捕获阶段只在命中网格后拦截点击，其余位置继续交给页面。这是几何网格检测，没有进一步读取纹理 alpha；网格里的透明留白仍可能造成误判。尾巴也经常被身体遮住，所以另外提供了身体动作池和方向键入口。

动作在 `beforeModelUpdate` 阶段写入模型参数。爱心眼使用 `Param4`，晕眩使用 `Param5`，生气使用 `Param63`，这些编号依赖当前模型，不能直接套到其他角色上。姿态通道采用指数平滑，再按模型声明的参数上下限裁剪：

```javascript
const alpha = 1 - Math.exp(-dt / 85);
blend[id] += (target - blend[id]) * alpha;
```

动作之间通过规则仲裁：主动回应只在没有动作或正在待机时进入，并有九秒冷却；点击和摸头可以接管待机；生气动作期间拒绝普通动作，晕眩保留恢复时间。每个点击区域使用洗牌后的动作池，先用完一轮再重排，避免连续随机抽到同一个动作。

正文选区通过 `selectionchange` 和指针释放事件读取，拖选途中不反复启动动作。有效选区会触发侧头观察，放大镜则是单独的 SVG 附件：从手部 `ArtMesh102` 网格取靠近末端的顶点，再经过模型局部变换和世界变换定位镜柄。镜片用 `textContent` 写入选区文字，不插入选区 HTML。附件不接收指针事件，因此不会抢走文本选择与复制；输入框和终端选区排除，切页与弹窗会清理附件。

终端输入 `rm -rf /*` 时发送 `terminal-catastrophe` 事件，角色控制器切到生气，另一个模块绘制核爆彩蛋。终端和角色不直接调用彼此的内部方法，特效结束后分别清理状态。

## 5. 主题切换和减少动态效果

页面通过根元素的 `data-theme` 切换 CSS 变量，偏好保存在 localStorage。初始化脚本放在样式加载前，先解析浅色、深色或跟随系统，减少首屏使用错误主题的机会。玻璃着色器也读取同一主题状态，调整采样后的色调和文字遮罩。

减少动态效果需要分别处理渲染循环。玻璃停止连续申请下一帧，主题和布局变化时仍可重绘；Live2D 停止 ticker，保留短暂的静态表情互动；终端默认暂停，允许用户主动播放。页面进入后台时也停止推进相关绘制或场景。

这只能控制本站主动调度的工作，不能据此推断低端设备一定流畅。玻璃的全屏着色和模型纹理仍有成本，目前限制了玻璃分辨率、模型分辨率和模型 30fps 上限，但没有完整的设备分档策略。

## 6. 内容输出与 SEO 共用元数据

文章的标题、摘要、分类、日期和标签来自 Markdown 文件头，`site/seo.js` 再生成 canonical、Open Graph、Twitter 标签及 JSON-LD。按站点设置，浏览器标题统一为「linfon18的小站」，文章标题保留在正文 H1 和结构化数据的 headline 中。

日期使用显式填写的值。没有日期的旧说明文不会被补成构建当天发布；RSS 仅在有发布日期时输出 pubDate，sitemap 的 lastmod 使用更新日期或发布日期。草稿在进入统一内容数组之前被排除，因此不会意外混入搜索和订阅。

静态资产地址则在构建末尾附加内容哈希：

```javascript
const version = crypto.createHash('sha256')
  .update(fs.readFileSync(asset))
  .digest('hex')
  .slice(0, 12);
```

HTML 中的本地样式、脚本和图标地址会带上这段版本号。这样资源内容改变时引用地址也跟着变化；EdgeOne 实际缓存行为仍取决于部署端的配置。

## 7. 验证范围与后续问题

这版构建使用 Node.js 14.21.3 实测。浏览器检查覆盖文章入口、搜索、RSS、sitemap、日期和来源标注，以及桌面和手机宽度下的亮暗色阅读。终端之前还检查了接管前后的节点身份、配色和恢复行为。

Live2D 的验证除了点击后的状态，还采集了实际模型参数，检查眨眼差异、表情、尾翼变化，以及参数是否有限并处于模型范围内。对应的功能、动作和主动行为共 71 项检查通过；这一组是此前模型更新的结果，不等于本次文章修改后重新跑了全部交互。

这些浏览器检查使用本机 Edge 和软件 WebGL，能够发现功能错误，不能作为真实手机 GPU 性能或所有浏览器兼容性的结论。接下来更值得补的是移动设备实测、玻璃绘制耗时统计，以及模型资源失败后的恢复。内容侧如果要继续支持图片、表格和更复杂的 Markdown，也需要扩展当前渲染器，而不是默认它已经兼容完整语法。
